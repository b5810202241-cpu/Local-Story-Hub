## Epic: การจัดการงาน (Task Management)

### BL-001: สร้างงานใหม่
- **Epic**: การจัดการงาน
- **User Story**: ในฐานะผู้ใช้ที่ล็อกอินแล้ว ฉันต้องการสร้างงานใหม่โดยระบุชื่อ รายละเอียด วันครบกำหนด และผู้รับผิดชอบ เพื่อให้ทีมทราบว่าต้องทำอะไรและใครรับผิดชอบ
- **Acceptance Criteria**:
  - Given ผู้ใช้ล็อกอินแล้ว When กรอกชื่องาน วันครบกำหนด และผู้รับผิดชอบครบถ้วน Then ระบบสร้างงานใหม่ด้วยสถานะ "ยังไม่เริ่ม"
  - Given ข้อมูลที่จำเป็นไม่ครบ When พยายามบันทึก Then ระบบไม่บันทึกและแจ้งฟิลด์ที่ขาด
- **Priority**: Must
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

### BL-002: แก้ไข/ลบงานของตนเอง
- **Epic**: การจัดการงาน
- **User Story**: ในฐานะผู้สร้างงาน ฉันต้องการแก้ไขหรือลบงานที่ตนเองสร้าง เพื่อปรับข้อมูลให้ถูกต้องเมื่อสถานการณ์เปลี่ยน
- **Acceptance Criteria**:
  - Given งานที่มีสถานะ "ยังไม่เริ่ม" หรือ "กำลังทำ" When ผู้สร้างงานแก้ไขวันครบกำหนด Then ระบบบันทึกการเปลี่ยนแปลง
  - Given งานที่มีสถานะ "เสร็จแล้ว" When พยายามแก้ไขวันครบกำหนด Then ระบบปฏิเสธ และต้องเปลี่ยนสถานะกลับเป็น "กำลังทำ" ก่อน (business rule จาก spec)
  - Given ผู้ใช้ที่ไม่ใช่ผู้สร้างงาน When พยายามแก้ไข/ลบ Then ระบบปฏิเสธ
- **Priority**: Must
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

### BL-003: ติดตามสถานะงาน
- **Epic**: การจัดการงาน
- **User Story**: ในฐานะผู้ใช้ ฉันต้องการเปลี่ยนสถานะงานระหว่าง "ยังไม่เริ่ม / กำลังทำ / เสร็จแล้ว" เพื่อสื่อสารความคืบหน้าให้ทีมทราบ
- **Acceptance Criteria**:
  - Given งานที่มีอยู่ When เปลี่ยนสถานะ Then ระบบรับได้เฉพาะ 3 ค่านี้เท่านั้น
- **Priority**: Should
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

## Epic: การจัดกลุ่มเป็นโปรเจกต์ (Project Grouping)

### BL-004: สร้างโปรเจกต์และผูกงานเข้ากับโปรเจกต์
- **Epic**: การจัดกลุ่มเป็นโปรเจกต์
- **User Story**: ในฐานะผู้ใช้ ฉันต้องการสร้างโปรเจกต์เพื่อรวมกลุ่มงานที่เกี่ยวข้องกัน เพื่อจัดระเบียบงานให้ดูง่ายขึ้น
- **Acceptance Criteria**:
  - Given ผู้ใช้ล็อกอินแล้ว When สร้างโปรเจกต์ใหม่ Then ระบบบันทึกโปรเจกต์และตั้งผู้สร้างเป็นเจ้าของ
  - Given งานหนึ่งชิ้น When ผูกเข้ากับโปรเจกต์ Then งานนั้นสังกัดได้เพียงโปรเจกต์เดียวเท่านั้น
- **Priority**: Must
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

### BL-005: ลบโปรเจกต์
- **Epic**: การจัดกลุ่มเป็นโปรเจกต์
- **User Story**: ในฐานะผู้สร้างโปรเจกต์ ฉันต้องการลบโปรเจกต์ที่ไม่ใช้แล้ว เพื่อให้รายการโปรเจกต์สะอาดเป็นระเบียบ
- **Acceptance Criteria**:
  - Given โปรเจกต์ที่ไม่มีงานค้างอยู่ When ผู้สร้างโปรเจกต์ลบ Then ระบบลบโปรเจกต์สำเร็จ
  - Given โปรเจกต์ที่ยังมีงานค้างอยู่ When พยายามลบ Then ระบบปฏิเสธและแจ้งให้จัดการงานที่ค้างก่อน
  - Given ผู้ใช้ที่ไม่ใช่ผู้สร้างโปรเจกต์ When พยายามลบ Then ระบบปฏิเสธ
- **Priority**: Should
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

## Epic: การแจ้งเตือน (Notifications)

### BL-006: แจ้งเตือนทางอีเมลก่อนครบกำหนด
- **Epic**: การแจ้งเตือน
- **User Story**: ในฐานะผู้รับผิดชอบงาน ฉันต้องการได้รับอีเมลแจ้งเตือนก่อนถึงวันครบกำหนด เพื่อไม่ให้งานล่าช้า
- **Acceptance Criteria**:
  - Given งานที่ยังไม่เสร็จและเปิดการแจ้งเตือนอยู่ When ถึงเวลา 1 วันก่อนวันครบกำหนด Then ระบบส่งอีเมลแจ้งเตือนถึงผู้รับผิดชอบ
- **Priority**: Should
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

### BL-007: ปิดการแจ้งเตือนรายโปรเจกต์
- **Epic**: การแจ้งเตือน
- **User Story**: ในฐานะผู้ใช้ ฉันต้องการปิดการแจ้งเตือนของบางโปรเจกต์ เพื่อลดอีเมลรบกวนสำหรับโปรเจกต์ที่ไม่ต้องติดตามใกล้ชิด
- **Acceptance Criteria**:
  - Given โปรเจกต์หนึ่ง When ผู้ใช้ปิดการแจ้งเตือนของโปรเจกต์นั้น Then ระบบไม่ส่งอีเมลแจ้งเตือนสำหรับงานในโปรเจกต์นั้นอีก
- **Priority**: Could
- **Source**: [[product-spec|product-spec]]
- **Status**: ยังไม่เริ่ม

## ข้อสันนิษฐาน

- spec ไม่ได้ระบุ priority ไว้ตรงๆ — priority ข้างต้นตั้งจาก scope statement ("สิ่งที่ทำ" 3 หัวข้อหลักถือเป็น Must/Should) ควรให้ Product Owner ยืนยันอีกครั้ง
- ถือว่า "ผู้รับผิดชอบ" ในงาน หมายถึงผู้ใช้ 1 คนต่องาน (ไม่รองรับหลายคนร่วมรับผิดชอบ) เพราะ spec ไม่ได้ระบุจำนวน
- ยังไม่มี backlog item สำหรับการจัดการผู้ใช้/ระบบล็อกอิน เพราะ spec ไม่ได้ระบุไว้ในขอบเขต แต่ถูกอ้างถึงโดยอ้อม ("ผู้ใช้ที่ล็อกอินแล้ว") — ควรตรวจสอบว่าอยู่ใน scope ของ spec อื่นหรือไม่
