## บั๊กที่พบ

ไม่พบบั๊กที่ทำให้ Then ของ TC ใดไม่เป็นจริง — พบข้อสังเกตความรุนแรง**ต่ำ**ที่ไม่กระทบผลการทดสอบหลัก 1 รายการ:

- **[ต่ำ] ข้อความสถานะไม่ตรงกันเมื่อบัญชีถูกปฏิเสธแล้ว navigate ตรงไปหน้าอื่นที่ไม่ใช่หน้า login** — ระหว่างทดสอบ TC-019 พบว่า session ของบัญชี Firebase Auth ที่ถูกปฏิเสธ**ไม่ได้ถูก sign-out อัตโนมัติ**หลัง login ล้มเหลว (ต่างจากที่อาจคาดไว้) เมื่อ navigate ตรงไปยัง `community-dashboard.html` หรือ `community-create-content.html` ด้วย session นี้ หน้าเหล่านั้นบล็อกการเข้าถึงถูกต้อง (ไม่รั่วข้อมูล/ฟีเจอร์ใดๆ ให้ใช้ ตรงตามเจตนาหลักของ Then) แต่ข้อความที่แสดงคือ **"บัญชีนี้ยังอยู่ในสถานะรออนุมัติ"** (ข้อความสำหรับสถานะ "รออนุมัติ") แทนที่จะเป็นข้อความเฉพาะของสถานะ "ไม่อนุมัติ" พร้อมเหตุผลแบบที่หน้า `community-register.html` แสดงถูกต้อง — ทำให้ผู้ใช้ที่ถูกปฏิเสธอาจเข้าใจผิดว่าแค่ต้อง "รอ" ต่อไป ทั้งที่ความจริงคือถูกปฏิเสธแล้วและต้องสมัครบัญชีใหม่เท่านั้น ไม่กระทบ Acceptance Criteria ของ TC-019 โดยตรง (ซึ่งทดสอบผ่าน flow login ที่ `community-register.html` ซึ่งแสดงข้อความถูกต้อง) แต่เป็นความไม่สอดคล้อง (consistency) ของ UX ที่ควรแก้ไข — แนะนำให้ทีมพัฒนาตรวจ guard function ใน `community-dashboard.html`/`community-create-content.html` ให้เช็ค field `status` ให้ครบทั้ง 3 ค่า (รออนุมัติ/อนุมัติแล้ว/ไม่อนุมัติ) แทนที่จะรวมเป็นข้อความเดียว

## สรุป

ทดสอบครบ 3/3 TC ในขอบเขตที่ได้รับมอบหมาย (TC-017–TC-019) — **ผ่านทั้งหมด 3 ข้อ** ไม่พบบั๊กที่ทำให้ Acceptance Criteria ไม่เป็นจริง ระบบสมัคร/อนุมัติ/ปฏิเสธบัญชีชุมชนใหม่ (BL-022) ทำงานถูกต้องครบทั้ง flow ตั้งแต่สมัคร → เข้าคิวรออนุมัติพร้อมแจ้งเตือนอาจารย์ (แบบแบนเนอร์จำลอง) → อนุมัติแล้วใช้งานฟีเจอร์หลักได้จริง (ยืนยันด้วยการสร้าง/เผยแพร่คอนเทนต์จริงสำเร็จ) → ปฏิเสธแล้วเข้าใช้งานไม่ได้พร้อมแจ้งเหตุผลชัดเจน ยืนยันด้วยการรีเฟรชหน้า/ทดสอบซ้ำหลังการเขียนข้อมูลทุกครั้ง พบข้อสังเกตความรุนแรงต่ำ 1 รายการเรื่องข้อความสถานะไม่สอดคล้องกันเมื่อบัญชีที่ถูกปฏิเสธพยายาม navigate ตรงไปหน้าอื่น (ไม่กระทบผลการทดสอบหลักหรือความปลอดภัย เพราะการเข้าถึงยังคงถูกบล็อกถูกต้อง) — เอกสารสถานะ backlog (`เสร็จแล้ว`) ตรงกับพฤติกรรมจริงที่ทดสอบ
