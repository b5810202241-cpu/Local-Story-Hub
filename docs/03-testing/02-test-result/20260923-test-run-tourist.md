## บั๊กที่พบ

### บั๊ก #1 (ความรุนแรง: กลาง-สูง) — สมัครบัญชีนักท่องเที่ยวใหม่ครั้งแรกดูเหมือนสำเร็จ แต่บัญชีนักท่องเที่ยว (touristAccounts) ไม่ถูกสร้างจริง

**พบระหว่าง**: ตั้งค่า Given ของ TC-007 (สมัครบัญชีนักท่องเที่ยวใหม่ผ่าน `tourist-login.html`)

**ขั้นตอนที่ทำ**:
1. เปิด `tourist-login.html` (มี query `redirect=...` กลับไปหน้าเรื่องราวที่กำลังดู)
2. กด "สมัครบัญชีใหม่" → กรอกชื่อที่แสดง/อีเมล/รหัสผ่านครบ → กด "สมัครและเข้าสู่ระบบ"
3. หน้าเว็บ redirect กลับไปหน้าเรื่องราวทันที **โดยไม่มี error ใดๆ แสดงให้เห็น** — ดูเหมือนสมัครสำเร็จสมบูรณ์

**ผลที่คาด**: หลัง redirect ควร login และใช้งานฟีเจอร์นักท่องเที่ยว (เขียนรีวิว/บันทึกสถานที่) ได้ทันที ตามที่ระบุใน `tourist-login.html` ("สมัครเสร็จใช้งานเขียนรีวิว/บันทึกสถานที่โปรดได้ทันที ไม่ต้องรอใครอนุมัติ")

**ผลจริง**: หน้าเรื่องราวที่ redirect ไปแสดง nav เป็น "ลงทะเบียนนักท่องเที่ยว" (เหมือนยังไม่ login) และส่วนรีวิวยังขึ้นข้อความ "ต้องเข้าสู่ระบบ/สมัครบัญชีก่อน" — รีเฟรชหน้าซ้ำก็ยังเป็นเช่นเดิม กลับไปที่ `tourist-login.html` อีกครั้งพบว่าระบบรู้จัก Firebase Auth session ถูกต้อง (อีเมลตรง) แต่ขึ้นการ์ด "ลงทะเบียนเป็นนักท่องเที่ยว" บอกว่า "บัญชีนี้ยังไม่เคยลงทะเบียนใช้งานฟีเจอร์นักท่องเที่ยว" — สรุปคือ **บัญชี Firebase Auth ถูกสร้างสำเร็จ แต่เอกสารใน collection `touristAccounts` ไม่ถูกสร้างจริง** ทั้งที่ไม่มี error message ใดๆ ปรากฏให้ผู้ใช้เห็นเลยตลอดขั้นตอน

**วิธี workaround ที่ใช้ได้**: กรอกชื่อที่แสดงซ้ำในการ์ด "ลงทะเบียนเป็นนักท่องเที่ยว" (complete-profile-view) แล้วกด "เริ่มใช้งาน" อีกครั้ง — รอบนี้บันทึกสำเร็จจริง (ยืนยันด้วยการนำทางไป `tourist-login.html` ซ้ำหลายครั้ง เห็น auto-redirect ถูกต้องทุกครั้ง ไม่ต้องกรอกชื่อซ้ำอีก)

**หมายเหตุสำหรับผู้พัฒนา**: อ่านโค้ด `tourist-login.html` (ไม่ได้ใช้เป็นเกณฑ์ตัดสินผล แต่ใช้เข้าใจ flow เพื่อรายงานให้ตรงจุด) พบว่า `submitRegister()` เรียก `await setDoc(...)` เขียน `touristAccounts/{uid}` หลังสร้างบัญชี Auth แล้วปล่อยให้ `onAuthStateChanged` (ที่ผูกไว้แยกต่างหากตั้งแต่โหลดหน้า) เป็นคนอ่าน `getDoc` แล้ว redirect เอง — มีความเป็นไปได้ที่จะเกิด race condition ระหว่างสอง flow นี้ (onAuthStateChanged อ่านเอกสารก่อนที่ setDoc จะเขียนเสร็จจริงบน server) ระหว่างการทดสอบยังสังเกตเห็น console error `net::ERR_CONNECTION_RESET`/`net::ERR_INTERNET_DISCONNECTED` บน Firestore Listen channel ช่วงเวลาใกล้เคียงกัน ซึ่งอาจเป็นปัจจัยร่วมทำให้ write ไม่ถูก sync ขึ้น server ก่อนที่ client จะเชื่อว่าสำเร็จแล้ว (optimistic write ของ Firestore SDK) — ไม่ยืนยันสาเหตุแน่ชัด 100% เพราะไม่ได้แก้โค้ดทดสอบซ้ำหลายรอบ (นอกขอบเขต QA) แต่ยืนยันแน่นอนว่า **เกิดขึ้นจริงกับ user flow ปกติอย่างน้อย 1 ครั้งจากการทดสอบจริง และไม่มี error แจ้งผู้ใช้เลย** ทำให้ผู้ใช้จริงอาจสับสนว่าทำไมเขียนรีวิว/บันทึกสถานที่ไม่ได้ทั้งที่เพิ่ง "สมัครสำเร็จ" — แนะนำให้เพิ่มการตรวจสอบ/แจ้งเตือนที่ชัดเจนกว่านี้ หรือย้ายการ redirect ให้ผูกกับผลลัพธ์ของ `setDoc` โดยตรงแทนที่จะพึ่ง `onAuthStateChanged` แยกทาง

### บั๊ก #2 (ความรุนแรง: ต่ำ) — ไม่มีหน้ารวมรายการ "สถานที่โปรด" ให้ดูภาพรวม

**พบระหว่าง**: ทดสอบ TC-008

Acceptance Criteria ของ BL-012 ระบุ "Then ระบบเก็บรายการสถานที่โปรดไว้ให้ดูภายหลังได้" — ทดสอบแล้วพบว่าระบบเก็บข้อมูลจริงและ toggle บันทึก/ยกเลิกทำงานถูกต้องต่อรายการเดียว (ยืนยันด้วยการรีเฟรช) แต่ตรวจสอบทั้งเว็บแล้วไม่พบหน้าใดที่แสดง "รายการ" สถานที่โปรดทั้งหมดของผู้ใช้ในที่เดียว (มีแค่ toggle ต่อหน้ารายละเอียดเรื่องราวแต่ละหน้าเท่านั้น) — นักท่องเที่ยวจึงดูภาพรวมสถานที่ที่เคยบันทึกไว้ไม่ได้ ต้องจำเองว่าเคยกดบันทึกเรื่องไหนไว้บ้างแล้วไปเปิดทีละหน้าเพื่อเช็ค ไม่ตรงกับเจตนาของ "ให้ดูภายหลังได้" แบบเต็มรูปแบบ — ไม่ได้ทำให้ TC-008 ไม่ผ่าน (เพราะกลไกหลักที่ AC ระบุ คือ "กดบันทึก → ระบบเก็บไว้" ทำงานถูกต้องจริง) แต่ควรพิจารณาเพิ่มหน้า "สถานที่โปรดของฉัน" ในรอบพัฒนาถัดไป

## ข้อมูลทดสอบที่สร้างไว้ในระบบ

- **บัญชีนักท่องเที่ยวทดสอบใหม่** (สมัครผ่านฟอร์มจริงตามที่ได้รับมอบหมาย):
  - อีเมล: `qa-tester-tourist-lsh@example.com`
  - รหัสผ่าน: `QaTester1234!`
  - ชื่อที่แสดง: `ทดสอบ QA นักท่องเที่ยว`
  - เก็บอยู่ใน Firebase Authentication + Firestore collection `touristAccounts` ของ project `lsh-nammon` จริง — ไม่มีปุ่มลบบัญชีตัวเองใน UI จึงปล่อยบัญชีนี้ค้างไว้ในระบบ (ตามกฎ ห้ามลบด้วยวิธีอื่นนอกจาก UI ปกติ)
- **รีวิว 1 รายการ** ใน collection `Reviews`: ผูกกับผลงานนิสิต "สารคดีสั้น เครื่องปั้นดินเผา ชาม สังคโลก" (`type=student`, `id=q2Yr5mQeV1Inkm3rmlsv`) ข้อความ "ทดสอบ QA: เดินทางไปเยี่ยมชมชุมชนบ้านผาบ่องมา ได้เห็นขั้นตอนการปั้นเครื่องปั้นดินเผาจริง น่าประทับใจมาก" — ไม่มีปุ่มลบ/แก้ไขรีวิวใน UI (ตามสเปค immutable) จึงปล่อยค้างไว้
- **บันทึกสถานที่โปรด 1 รายการ** ใน collection `Bookmarks`: บัญชีทดสอบข้างต้น บันทึกผลงาน "สารคดีสั้น เครื่องปั้นดินเผา ชาม สังคโลก" ไว้ (`doc id` รูปแบบ `{touristId}_student_q2Yr5mQeV1Inkm3rmlsv`) — สามารถลบได้จริงผ่าน UI (กดปุ่ม "บันทึกแล้ว ✓ (กดเพื่อยกเลิก)" ซ้ำ) แต่ตั้งใจปล่อยไว้เป็นหลักฐานผลทดสอบ ไม่ได้ลบ
- **ConsentRecords 1 รายการ**: เขียนโดยบัญชี/เบราว์เซอร์ที่ใช้ทดสอบตอนกด "ปฏิเสธที่ไม่จำเป็น" (TC-002) — เขียนอัตโนมัติจาก `consent-banner.js` ไม่มี UI ให้ลบ

> หมายเหตุเพิ่มเติม: พบว่าเบราว์เซอร์ที่ใช้ทดสอบมีสถานะ login ค้างจากรอบทดสอบก่อนหน้า (บัญชีอาจารย์ `u004@example.com`) ตั้งแต่ก่อนเริ่มงานนี้ — ได้ logout บัญชีนั้นออกจากหน้า `tourist-login.html` ก่อนเริ่มสมัครบัญชีนักท่องเที่ยวทดสอบใหม่ ไม่ได้แก้ไข/ลบข้อมูลใดๆ ของบัญชี `u004` เอง
