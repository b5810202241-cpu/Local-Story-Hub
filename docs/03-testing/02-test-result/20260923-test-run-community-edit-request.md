- **ผู้ทดสอบ**: QA agent (จำลองผู้ใช้มือใหม่ ทดสอบผ่าน UI จริงทั้งหมด ไม่อ่าน source code เพื่อสรุปผล — อ่าน source code เฉพาะตอนสืบสวนบั๊กหลังพบความผิดปกติจาก UI แล้วเท่านั้น)

## บั๊กที่พบ

- **[ปานกลาง] ระบบไม่แจ้งเหตุผลการไม่อนุมัติคำขอแก้ไขกลับไปยังชุมชนเลย (ครึ่งหลังของ Then ของ TC-022 ไม่เป็นจริง)** — Acceptance Criteria ของ BL-023 (และ Then ของ TC-022) ระบุชัดเจนว่า "ระบบไม่นำการแก้ไขไปใช้ **และแจ้งเหตุผลกลับไปยังชุมชน**" แต่ทดสอบจริงพบว่าเมื่ออาจารย์กด "ไม่อนุมัติ" คำขอแก้ไข ฝั่งชุมชนไม่มีทางรับรู้เลยว่าคำขอถูกปฏิเสธ ไม่ต้องพูดถึงเหตุผล — ตรวจสอบ source code ยืนยันสาเหตุ: `community-dashboard.html` (บรรทัด 181) query คอลเลกชัน `ContentEditRequests` เฉพาะ `where('status', '==', 'รอพิจารณา')` เท่านั้น ใช้แค่กำหนดว่าจะแสดงปุ่ม "ขอแก้ไข" หรือ badge "มีคำขอแก้ไขรอพิจารณา" — ไม่เคย query หรือแสดงคำขอที่ `status` เป็น `อนุมัติ`/`ไม่อนุมัติ` เลย ส่วน `community-request-edit.html` เขียน field `rejectionReason: null` ตอนสร้างคำขอ (บรรทัด 218) แต่ไม่มีจุดใดใน 3 ไฟล์ที่แตะ `ContentEditRequests` (`admin-review-student-work.html`, `community-dashboard.html`, `community-request-edit.html`) ที่อ่าน field นี้กลับมาแสดงฝั่งชุมชนเลย — เหตุผลที่อาจารย์กรอกไว้ถูกเก็บและแสดงถูกต้องเฉพาะในตาราง "ประวัติคำขอแก้ไขข้อมูลชุมชนที่พิจารณาแล้ว" ของหน้าอาจารย์เท่านั้น (ฝั่งเดียว) — ผลกระทบ: ชุมชนที่ถูกปฏิเสธคำขอจะเห็นแค่ปุ่ม "ขอแก้ไข" กลับมาใช้งานได้ตามปกติโดยไม่มีคำอธิบายใดๆ ทำให้แยกไม่ออกระหว่าง "ไม่เคยส่งคำขอ" กับ "ส่งคำขอไปแล้วถูกปฏิเสธ" สร้างความสับสนและอาจทำให้ส่งคำขอเดิมซ้ำโดยไม่รู้ว่าทำไมครั้งก่อนไม่ผ่าน — ไม่กระทบความปลอดภัย/ความถูกต้องของข้อมูล (คอนเทนต์จริงไม่ถูกแก้ไขอย่างถูกต้อง) จึงไม่ใช่บั๊กความรุนแรงสูง แต่กระทบ UX/การสื่อสารตรงตาม Acceptance Criteria ที่ระบุไว้ชัดเจน แนะนำให้ทีมพัฒนาเพิ่ม query/UI ฝั่งชุมชนให้แสดงคำขอที่พิจารณาแล้ว (โดยเฉพาะที่ถูกปฏิเสธ) พร้อมเหตุผล เช่น เพิ่ม section "ประวัติคำขอแก้ไขของคุณ" ใน `community-dashboard.html` คล้ายกับที่ `admin-review-student-work.html` มีอยู่แล้วฝั่งอาจารย์

  2. คำขอที่ 2 (TC-022) — ขอเปลี่ยนชื่อเป็น `ทดสอบ QA - ทดสอบสิทธิ์ชุมชนอนุมัติ (คำขอที่ 2 จะถูกปฏิเสธ TC-022)`, สถานะ: **ไม่อนุมัติ**, เหตุผล: `ทดสอบ QA: ปฏิเสธคำขอแก้ไขนี้โดยตั้งใจเพื่อทดสอบ TC-022 (เนื้อหาที่ขอแก้ไขไม่เหมาะสมกับบริบทของคอนเทนต์ — เหตุผลจำลองสำหรับทดสอบ)` (บันทึกโดย `u004@example.com`)

## สรุป

ทดสอบครบ 3/3 TC ในขอบเขตที่ได้รับมอบหมาย (TC-020–TC-022) — **ผ่าน 2 ข้อ (TC-020, TC-021), ไม่ผ่าน 1 ข้อ (TC-022)** กลไกหลักของ BL-023 (ส่งคำขอแก้ไข → สถานะ "รอพิจารณา" ไม่มีผลจริงทันที → อาจารย์อนุมัติแล้วนำไปใช้จริงทันที / ไม่อนุมัติแล้วคอนเทนต์ไม่เปลี่ยน) ทำงานถูกต้องครบถ้วน ยืนยันด้วยการรีเฟรชหน้า/ตรวจสอบคอนเทนต์จริงทั้งฝั่งชุมชนและฝั่งสาธารณะหลังการเขียนข้อมูลทุกครั้ง — แต่พบบั๊กความรุนแรงปานกลาง 1 รายการที่ TC-022: ระบบไม่แจ้งเหตุผลการไม่อนุมัติกลับไปยังชุมชนเลยตามที่ Acceptance Criteria ระบุไว้ชัดเจน (ไม่มี UI ฝั่งชุมชนจุดใดแสดงคำขอที่ถูกปฏิเสธหรือเหตุผล) — เอกสารสถานะ backlog (`เสร็จแล้ว`) **ไม่ตรงกับพฤติกรรมจริงทั้งหมด** เนื่องจากส่วน "แจ้งเหตุผลกลับไปยังชุมชน" ของ Acceptance Criteria ข้อที่ 3 ยังไม่ได้ implement จริง แนะนำให้ทีมพัฒนาแก้ไขก่อนปิดสถานะ BL-023 ว่าเสร็จสมบูรณ์
