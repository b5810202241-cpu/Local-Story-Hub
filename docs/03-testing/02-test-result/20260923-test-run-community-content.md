ทดสอบผ่านเบราว์เซอร์จริง (Playwright MCP) กับเว็บที่ deploy จริงที่ [https://lsh-nammon.web.app/](https://lsh-nammon.web.app/) (production Firebase project `lsh-nammon`) ตามขอบเขตที่ได้รับมอบหมาย — เฉพาะ **TC-009 ถึง TC-016** (หมวด "ชุมชน — สร้าง/จัดการคอนเทนต์") ใน [[../01-test-plan/test-plan|test-plan]] เท่านั้น

- **ผู้ทดสอบ**: QA agent (จำลองผู้ใช้มือใหม่ ทดสอบผ่าน UI จริงทั้งหมด ไม่อ่าน source code เพื่อสรุปผล)
- **บัญชีทดสอบที่ใช้**: บัญชีชุมชนเดิม "ชุมชนทดสอบผาบ่อง QA" จากรอบก่อนไม่มีรหัสผ่านที่บันทึกไว้ในเอกสารใดๆ (ตรวจสอบ `LSH/DEMO_CREDENTIALS.md` และ `docs/05-log/index.md` แล้วไม่พบ) จึง**สมัครบัญชีชุมชนใหม่ผ่านฟอร์มจริง** ("ทดสอบ QA ชุมชนบ้านผาบ่อง 2") แล้วอนุมัติเองด้วยบัญชีอาจารย์ (`u004@example.com` จาก `LSH/DEMO_CREDENTIALS.md`) ผ่าน `admin-review-student-work.html` — ดูรายละเอียดที่หัวข้อ "ข้อมูลทดสอบที่สร้างไว้ในระบบ" ด้านล่าง

## ข้อมูลทดสอบที่สร้างไว้ในระบบ

- **บัญชีชุมชนทดสอบใหม่** (สมัครผ่านฟอร์มจริงตามที่ได้รับมอบหมาย เพราะไม่มีรหัสผ่านของบัญชี "ชุมชนทดสอบผาบ่อง QA" เดิมบันทึกไว้ที่ใดเลย):
  - อีเมล: `qa-tester-community-lsh@example.com`
  - รหัสผ่าน: `QaTester1234!`
  - ชื่อชุมชน: `ทดสอบ QA ชุมชนบ้านผาบ่อง 2`
  - ข้อมูลยืนยันตัวตน: `ทดสอบ QA ผู้ติดต่อ, โทร. 08x-xxx-xxxx`
  - สถานะ: อนุมัติแล้ว (อนุมัติเองผ่าน `admin-review-student-work.html` ด้วยบัญชีอาจารย์ `u004@example.com`)
  - เก็บอยู่ใน Firebase Authentication + Firestore collection `users` (`role: 'community'`, `status: 'อนุมัติแล้ว'`) ของ project `lsh-nammon` จริง — ไม่มีปุ่มลบบัญชีตัวเองใน UI จึงปล่อยบัญชีนี้ค้างไว้ในระบบ (ตามกฎ ห้ามลบด้วยวิธีอื่นนอกจาก UI ปกติ)
- **คอนเทนต์ที่เผยแพร่ 1 รายการ** ใน collection `CommunityContent`: หัวข้อ "ทดสอบ QA - เรื่องเล่าสานส้มหมู่บ้าน" (`documentId: 6qCmvQjYM3MzfjjFtHmc`), เนื้อหา "เนื้อหาทดสอบ QA: ชุมชนของเรามีการเลี้ยงหมูกอนเป็นอาชีพเสริมมานานกว่า 50 ปี", `status: 'เผยแพร่แล้ว'`, ผูกกับบัญชีชุมชนทดสอบข้างต้น — ยืนยันคงอยู่จริงหลังรีเฟรชหน้า ไม่มีปุ่มลบคอนเทนต์ใน UI (มีแค่ "ขอแก้ไข" ซึ่งต้องผ่านอนุมัติ) จึงปล่อยค้างไว้เป็นหลักฐาน
- **บัญชีชุมชนเดิมจากรอบก่อน** ("ชุมชนทดสอบผาบ่อง QA") ยังคงอยู่ในระบบตามเดิม ไม่ได้แก้ไข/ลบข้อมูลใดๆ — แค่ไม่สามารถ login เข้าใช้ได้ในรอบนี้เพราะไม่มีรหัสผ่านที่บันทึกไว้ (ควรพิจารณาบันทึก credential ของบัญชีทดสอบไว้ในที่ปลอดภัยที่ agent รอบถัดไปเข้าถึงได้ เพื่อลดการสร้างบัญชีทดสอบซ้ำซ้อนขึ้นเรื่อยๆ)

## สรุป

ทดสอบครบ 8/8 TC ในขอบเขตที่ได้รับมอบหมาย (TC-009–TC-016) — ผ่าน 2 (TC-009, TC-016), บล็อก 4 (TC-012–015 ทั้งหมดเพราะ Cloudflare Worker ยังไม่ deploy ตามที่ทราบล่วงหน้า ไม่ใช่บั๊ก), ข้าม 2 (TC-010, TC-011 เพราะ BL-001 ยังไม่เริ่ม implement) ไม่พบบั๊กใดๆ ในรอบทดสอบนี้ ระบบจัดการคอนเทนต์ของชุมชน (BL-006) และหน้าจอที่อ่านง่ายสำหรับผู้สูงอายุ (BL-007) ทำงานถูกต้องตรงตาม Acceptance Criteria ทั้งคู่ ยืนยันด้วยการรีเฟรชหน้าซ้ำหลังการเขียนข้อมูลทุกครั้ง
