# Test Plan — สอดคล้องกับ User Journey

สร้าง test case จาก User Journey ทุกไฟล์ใน [[../../02-design/01-prototypes/index|02-design/01-prototypes]] โดยแปลง Acceptance Criteria ของ backlog item ที่แต่ละ journey step อ้างอิงให้เป็น test case โดยตรง (ไม่ได้แต่ง test case ใหม่ที่ไม่มีอ้างอิงใน Acceptance Criteria เดิม)

> **ขอบเขต**: ครอบคลุมเฉพาะ backlog item ที่ปรากฏเป็น step ใน User Journey ที่มีอยู่ — เหลือเพียง BL-014, BL-017 (log/consent evidence — พฤติกรรม backend ล้วน ไม่มี step ใน journey ใดโดยตรง) ที่ยังไม่อยู่ใน test plan ฉบับนี้ (ดูหัวข้อ "Backlog ที่ยังไม่มี Test Case" ท้ายไฟล์) — BL-019, BL-020, BL-021 ปิดช่องว่างแล้วเมื่อ 2026-09-22 หลังสร้าง journey ใหม่ 2 ไฟล์รองรับ
>
> **สถานะรวม**: ทุก test case เป็น **ยังไม่ทดสอบ** เพราะยังไม่มีซอร์สโค้ด backend จริงให้ทดสอบตามเกณฑ์นี้ (ดู `CLAUDE.md`) — เอกสารนี้เตรียมไว้ล่วงหน้าเพื่อให้พร้อมทดสอบทันทีที่มีระบบจริง — test case ที่มาจาก journey step ที่ยังเป็น DRAFT (ขึ้นกับ Open Question) ถูกทำเครื่องหมายไว้ในคอลัมน์หมายเหตุ ต้องยืนยัน requirement ให้นิ่งก่อนถือเป็น test case สุดท้าย

## Backlog ที่ยังไม่มี Test Case

- **BL-014, BL-017** (พฤติกรรม backend/log — ไม่มี step ใน journey ใดโดยตรงเพราะเกิดอัตโนมัติทุกคำขอ ไม่ใช่การกระทำที่ผู้ใช้ริเริ่มเอง) — **อัปเดต 2026-09-22**: technical design เสร็จสมบูรณ์แล้ว ([[../../02-design/02-technical/detailed-design|detailed-design]] Sequence #1 ครอบคลุม BL-017, Sequence #7 ใหม่ครอบคลุม BL-014 รวม retention 90 วัน) แต่ยังไม่สามารถแปลงเป็น test case แบบ journey-based ในไฟล์นี้ได้ตามกฎของ `test-cases` skill (ต้องมี step ใน User Journey) — เมื่อเริ่มมีโค้ดจริงให้ทดสอบ ควรเพิ่มเป็น **test case แบบ backend/integration test แยกต่างหาก** (ไม่ผูกกับ journey) แทน ไม่ใช่บังคับสร้าง journey step ปลอมขึ้นมาเพื่อให้เข้าเกณฑ์นี้เท่านั้น
