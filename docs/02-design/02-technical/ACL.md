# ACL — สิทธิ์การเข้าถึง: ระบบตรวจสอบผลงานนิสิต, สมัคร/อนุมัติบัญชี, ดูผลงานแบบ Public, จัดการข้อมูลชุมชน, และบัญชีนักท่องเที่ยว

ตารางสิทธิ์นี้ครอบคลุม 6 flow ของ **Local Story Hub**: (1) ส่ง/ตรวจสอบผลงานนิสิต — บทบาท **อาจารย์**/**นิสิต** อ้างอิงจาก FR-3.1 ([[../../01-requirements/01-spec/local-story-hub|local-story-hub]]), BL-018 ([[../../01-requirements/03-task/product-backlog|product-backlog]]) (2) สมัคร/อนุมัติบัญชีผู้ใช้ใหม่ (เพิ่ม 2026-09-12) — อ้างอิงจาก [[../../01-requirements/01-spec/20260912-01-account-registration-approval|20260912-01-account-registration-approval]], BL-019, BL-020 (3) ดู/ค้นหาผลงานที่เผยแพร่แล้วแบบไม่ login (เพิ่ม 2026-09-12) — บทบาท **บุคคลทั่วไป** อ้างอิงจาก [[../../01-requirements/01-spec/20260912-02-public-view-search-published-works|20260912-02-public-view-search-published-works]], BL-021 (4) จัดการคอนเทนต์ของชุมชน (เพิ่ม 2026-09-22) — บทบาท **ชุมชน**/**อาจารย์** อ้างอิงจาก FR-1.1–1.6, BL-001–006 (5) สมัคร/อนุมัติบัญชีชุมชนใหม่ + ขอแก้ไขข้อมูลชุมชน (เพิ่ม 2026-09-22) — อ้างอิงจาก Business Rules ใน [[../../01-requirements/01-spec/local-story-hub|local-story-hub]] (ตัดสินใจ 2026-09-22), BL-022, BL-023 (6) สมัครบัญชี + เขียนรีวิว/บันทึกสถานที่โปรดของนักท่องเที่ยว (เพิ่ม 2026-09-22) — บทบาท **นักท่องเที่ยว (มีบัญชี)** อ้างอิงจาก FR-2.4, FR-2.5, BL-011, BL-012 และ Decision Log 2026-08-28 ใน [[architecture|architecture.md]] ทุก flow อ้างอิง entity `StudentWork`/`UserAccount`/`Content`/`ContentEditRequest`/`Review`/`Bookmark` ใน [[architecture|architecture.md]]

> **"บุคคลทั่วไป" ในตารางด้านล่างหมายถึงผู้เยี่ยมชมที่ไม่ login เลยเท่านั้น** แคบกว่าบทบาท "นักท่องเที่ยว (มีบัญชี)" ที่แยกแถวต่างหากด้านล่าง (เพิ่ม 2026-09-22 ปิดช่องว่างที่เคยระบุไว้ในไฟล์นี้)

**สถานะการบังคับใช้:**
- **flow ตรวจสอบผลงานนิสิต (อัปเดต 2026-09-11):** บังคับใช้จริงแล้วทั้งสองระดับใน [[../01-prototypes/prototype-v2/README|prototype-v2]] — (1) UI ซ่อนปุ่ม/เมนูที่ไม่ตรงสิทธิ์ หลัง login ด้วย Firebase Authentication จริง และ (2) `LSH/firestore.rules` บังคับที่ backend ด้วย (ทดสอบยิง request ตรงข้าม UI แล้วว่าบล็อกจริง)
- **flow สมัคร/อนุมัติบัญชีผู้ใช้ใหม่ (อัปเดต 2026-09-12):** บังคับใช้จริงแล้วเช่นกัน — implement ใน [[../01-prototypes/prototype-v2/README|prototype-v2]] ทั้ง UI (หน้าสมัครสมาชิก + รายการรออนุมัติของอาจารย์ + แบนเนอร์แจ้งเตือนจำลอง) และ backend (`LSH/firestore.rules` บังคับ role/status ตอนสมัคร, จำกัด field ที่แก้ไขได้ตอนอนุมัติ) — ทดสอบยิง request ตรงข้าม UI แล้วว่าบล็อกจริง (ส่งผลงานทั้งที่บัญชียังไม่อนุมัติ, self-approve ตัวเอง, อ่านข้อมูล user คนอื่น)
- **flow ดูผลงานแบบ public (อัปเดต 2026-09-12):** บังคับใช้จริงแล้ว — หน้าใหม่ [[../01-prototypes/prototype-v2/README|prototype-v2/published-works.html]] อ่าน `LSHRequests` แบบไม่ login ได้ (ค้นหาตามชุมชนแบบ live) `LSH/firestore.rules` บังคับที่ backend ให้เห็นเฉพาะ `status='อนุมัติ'` เท่านั้น — ทดสอบยิง request ตรงข้าม UI แล้วว่าบล็อกจริงทั้งการอ่านเอกสารที่ยังไม่อนุมัติโดยตรง และการ list ทั้ง collection แบบไม่กรอง
- **flow จัดการคอนเทนต์ชุมชน + สมัคร/อนุมัติบัญชีชุมชน + ขอแก้ไขข้อมูล (เพิ่ม 2026-09-22):** ยังเป็น **conceptual เท่านั้น** (มาจาก `architecture-design`/`data-api-design` รอบ 2026-09-22) — ยังไม่มี prototype/backend จริงรองรับ ต่างจาก flow อื่นที่ implement และทดสอบจริงแล้ว
- **flow บัญชีนักท่องเที่ยว (เพิ่ม 2026-09-22):** บังคับใช้จริงแล้วใน [[../01-prototypes/prototype-v1/README|prototype-v1]] — เพิ่มหน้า `tourist-login.html` (สมัคร/login) และ gate ปุ่มเขียนรีวิว/บันทึกสถานที่ใน `tourist-story-detail.html` ให้เช็ค session ก่อนเสมอ — **เป็นการบังคับที่ระดับ UI ผ่าน `localStorage` เท่านั้น ไม่มี backend/security rules จริงรองรับ** (นักท่องเที่ยวยังไม่มี collection จริงใน Firestore ต่างจากนิสิต/อาจารย์) ทดสอบผ่าน browser แล้วว่า UI บล็อกถูกต้อง แต่ยังไม่มีการบังคับสิทธิ์ระดับ backend เหมือน flow อื่นที่ต่อ Firestore จริง

## AI ช่วยงาน (เพิ่ม 2026-09-19) — สรุปให้อ่าน ไม่ตัดสินแทน

[[../01-prototypes/prototype-v2/README|prototype-v2]] มีปุ่ม AI ช่วย 2 จุด (ระดับ 1: ช่วยปรับปรุงคำอธิบายผลงานใน
`student-publish.html`, ระดับ 2: สรุปภาพรวมผลงานที่รอพิจารณาใน `admin-review-student-work.html`) — ทั้งสอง
จุดยึดกฎเดียวกัน: **AI มีหน้าที่แค่สรุป/ช่วยร่างให้คนอ่านหรือแก้ต่อเท่านั้น ไม่มีสิทธิ์เปลี่ยนสถานะจริงใดๆ**
(`LSHRequests.status`, `users.status`) — การเปลี่ยนสถานะจริง (อนุมัติ/ไม่อนุมัติผลงานหรือบัญชี) ต้องเกิดจาก
การกดปุ่มของอาจารย์เอง (role=`teacher`) เท่านั้น ทั้ง UI (ปุ่ม AI ไม่มี path ใดที่ไปเรียก `updateDoc` กับ field
`status`) และ backend (`LSH/firestore.rules` — `AiSummaries` เป็นคนละ collection จาก `LSHRequests`/`users`
เขียนได้แต่ไม่มีผลต่อ workflow อนุมัติ, ส่วน `LSHRequests`/`users` ยังคง `allow update: if ... getRole() ==
'teacher'` เหมือนเดิม ไม่มีข้อยกเว้นให้ AI หรือ service account อื่นใดเขียนสถานะแทนได้)

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|

| **อาจารย์** (`role: teacher` ใน Firestore `users` จริง — คนละคำกับ `role: admin` ที่ entity `UserAccount` เชิงแนวคิดใช้ ดูตาราง Mapping ใน [[architecture|architecture.md]]) | - ดูรายการผลงานนิสิตที่รอพิจารณา (BL-018)<br>- อนุมัติผลงาน → เผยแพร่ได้<br>- ไม่อนุมัติผลงาน พร้อมระบุเหตุผลบังคับ<br>- ดูประวัติผลงานที่เคยตรวจสอบไปแล้ว (อนุมัติ/ไม่อนุมัติ)<br>- ได้รับอีเมลแจ้งเตือนเมื่อมีบัญชีผู้ใช้ใหม่รออนุมัติ — นิสิต (BL-020) หรือชุมชน (BL-022, เพิ่ม 2026-09-22)<br>- ดูรายการบัญชีผู้ใช้ใหม่ที่รออนุมัติ และอนุมัติ/ไม่อนุมัติพร้อมระบุเหตุผลได้ — ทั้งนิสิต (BL-020) และชุมชน (BL-022, เพิ่ม 2026-09-22)<br>- ได้รับอีเมลแจ้งเตือนเมื่อมีคำขอแก้ไขข้อมูลชุมชนรอพิจารณา (BL-023, เพิ่ม 2026-09-22)<br>- ดูรายการคำขอแก้ไขข้อมูลชุมชนที่รอพิจารณา และอนุมัติ/ไม่อนุมัติพร้อมระบุเหตุผลได้ (BL-023, เพิ่ม 2026-09-22) | - ส่งผลงานแทนนิสิต (ไม่มีข้อกำหนดให้ทำได้ — บทบาทนี้ระบุไว้เฉพาะการตรวจสอบ/อนุมัติ)<br>- แก้ไขคอนเทนต์/ข้อมูลชุมชนแทนชุมชนเอง (ไม่มีข้อกำหนดให้ทำได้ — ทำได้แค่อนุมัติ/ไม่อนุมัติคำขอที่ชุมชนส่งมา)<br>- **แก้ไขเนื้อหาผลงานของนิสิตโดยตรง** (เช่น แก้คำอธิบายเอง) — ทำได้แค่**อนุมัติ/ไม่อนุมัติ**เท่านั้น ถ้าไม่พอใจต้องไม่อนุมัติพร้อมเหตุผลแล้วให้นิสิตแก้เอง (ตัดสินใจ 2026-09-23) |
| **ชุมชน** (`role: community` — เพิ่ม 2026-09-22) | - สมัครบัญชีผู้ใช้ใหม่ได้เอง พร้อมข้อมูลยืนยันตัวตน ก่อนมีบัญชี (BL-022)<br>- สร้าง/จัดการคอนเทนต์ (เรื่องราว/สื่อ) ของชุมชนตนเอง ด้วยเครื่องมือ AI (ปรับภาพ, แคปชัน, แปลภาษา, SEO, แนะนำการเล่าเรื่อง) แล้วเผยแพร่ได้เองทันทีโดยไม่ต้องรออนุมัติ (FR-1.1–1.6, BL-001–006 — ไม่เปลี่ยนแปลงจากเดิม)<br>- ดูคอนเทนต์ของชุมชนอื่นได้ (ข้อมูลใช้ร่วมกันระหว่างชุมชน ไม่ isolate เต็มรูปแบบ — Business Rule ตัดสินใจ 2026-09-22)<br>- ส่งคำขอแก้ไขคอนเทนต์ของชุมชนตนเองที่เผยแพร่ (published) ไปแล้ว ไปรอการอนุมัติจากอาจารย์/แอดมินก่อนจึงจะมีผลจริง (BL-023)<br>- เห็นเหตุผลที่อาจารย์/แอดมินระบุ เมื่อบัญชีหรือคำขอแก้ไขไม่ผ่านการอนุมัติ | - แก้ไขคอนเทนต์ที่เผยแพร่ (published) แล้วให้มีผลทันทีโดยไม่ผ่านอนุมัติ — ต้องส่งเป็นคำขอก่อนเสมอ (BL-023) ต่างจากการสร้าง/เผยแพร่คอนเทนต์ใหม่ครั้งแรกซึ่งยังทำได้เองทันที (BL-006)<br>- อนุมัติ/ไม่อนุมัติบัญชีชุมชนอื่นหรือคำขอแก้ไขข้อมูล (ของตนเองหรือผู้อื่น) — เป็นสิทธิ์ของอาจารย์/แอดมินเท่านั้น<br>- **login เข้าใช้งานฟีเจอร์หลักไม่ได้ ถ้าบัญชีอยู่ในสถานะ "รออนุมัติ" หรือ "ถูกปฏิเสธ"** (BL-022) — เหมือนกฎของนิสิต<br>- **แก้ไขหรือยกเลิกคำขอแก้ไขที่ส่งไปแล้วขณะสถานะยังเป็น "รอพิจารณา" (pending)** — ต้องรอผลอนุมัติ/ไม่อนุมัติจากอาจารย์/แอดมินก่อนเสมอ (ตัดสินใจ 2026-09-23) ถ้าไม่ผ่านอนุมัติ ค่อยส่งคำขอใหม่ได้ |
| **นักท่องเที่ยว (มีบัญชี)** (`role: tourist` — เพิ่ม 2026-09-22) | - สืบค้น/ดูแหล่งท่องเที่ยวชุมชน, อ่าน/ฟังเรื่องราว, ดูหมุดหมายเดินทาง โดย**ไม่ต้อง login** เหมือนบุคคลทั่วไป (FR-2.1–2.3)<br>- สมัครบัญชีผู้ใช้ใหม่ได้เอง — **ใช้งานฟีเจอร์หลักได้ทันทีหลังสมัคร ไม่ต้องรออนุมัติ** (ต่างจากนิสิต/ชุมชนที่ต้องรออาจารย์อนุมัติก่อน — Decision Log 2026-08-28 ระบุแค่ "ต้องมีบัญชี" ไม่มีขั้นตอนอนุมัติ)<br>- เขียนรีวิวสถานที่ (BL-011)<br>- บันทึก/ยกเลิกบันทึกสถานที่โปรด (BL-012) | - เขียนรีวิวหรือบันทึกสถานที่โปรดโดย**ไม่มีบัญชี/ไม่ login** — ต้องสมัคร/เข้าสู่ระบบก่อนเสมอ (Decision Log 2026-08-28, แก้ไขให้ตรงกันแล้ว 2026-09-22)<br>- ทำการกระทำที่เป็นสิทธิ์ของบทบาทอื่น (ส่งผลงานนิสิต, อนุมัติบัญชี/ผลงาน, จัดการคอนเทนต์ชุมชน ฯลฯ) |
| **บุคคลทั่วไป** (ไม่ login — เพิ่ม 2026-09-12) | - ดูผลงานนิสิตที่มีสถานะ "อนุมัติ" (เผยแพร่แล้ว) เท่านั้น (BL-021)<br>- ค้นหา/กรองผลงานที่เผยแพร่แล้วตามชื่อชุมชนที่สนใจ (BL-021)<br>- สืบค้น/อ่านเรื่องราวชุมชนได้เช่นเดียวกับนักท่องเที่ยวที่มีบัญชี (FR-2.1–2.3 ไม่ต้อง login) | - ดู/เข้าถึงผลงานที่สถานะ "รอพิจารณา" หรือ "ไม่อนุมัติ" ไม่ว่าทางใด<br>- ทำการกระทำอื่นใดทั้งหมด (ส่งผลงาน, สมัครบัญชี, อนุมัติ/ไม่อนุมัติ, รีวิว, บันทึกสถานที่โปรด ฯลฯ) — ต้อง login เท่านั้น |

## สถานะบัญชี (Account Status) — เงื่อนไขเพิ่มเติมนอกเหนือจาก role

เฉพาะบัญชี **นิสิต** และ **ชุมชน** (เพิ่ม 2026-09-22, BL-022) ที่สมัครเองเท่านั้นที่มีสถานะนี้ (บัญชีอาจารย์ provision โดย admin ถือเป็น approved ทันที ไม่ผ่าน flow นี้) — **บัญชีนักท่องเที่ยวไม่มีสถานะนี้เลย** (เพิ่ม 2026-09-22): สมัครเสร็จใช้งานฟีเจอร์หลัก (รีวิว/บันทึกสถานที่) ได้ทันที ไม่ต้องรอใครอนุมัติ ต่างจากนิสิต/ชุมชนที่ต้องรออาจารย์/แอดมินอนุมัติก่อน:

| สถานะ | เข้าใช้งานฟีเจอร์หลักได้ไหม |
|---|---|
| รออนุมัติ (pending_approval) | ไม่ได้ — รอให้อาจารย์/แอดมินอนุมัติก่อน |
| อนุมัติแล้ว (approved) | ได้ ตามสิทธิ์ role=นิสิต หรือ role=ชุมชน ด้านบน |
| ไม่อนุมัติ (rejected) | ไม่ได้ — สถานะสิ้นสุด ต้องสมัครบัญชีใหม่เท่านั้น |
