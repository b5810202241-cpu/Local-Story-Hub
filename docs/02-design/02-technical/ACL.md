# ACL — สิทธิ์การเข้าถึง: ระบบตรวจสอบผลงานนิสิต, สมัคร/อนุมัติบัญชี, และดูผลงานแบบ Public

ตารางสิทธิ์นี้ครอบคลุม 3 flow ของ **Local Story Hub**: (1) ส่ง/ตรวจสอบผลงานนิสิต — บทบาท **อาจารย์**/**นิสิต** อ้างอิงจาก FR-3.1 ([[../../01-requirements/01-spec/local-story-hub|local-story-hub]]), BL-018 ([[../../01-requirements/03-task/product-backlog|product-backlog]]) (2) สมัคร/อนุมัติบัญชีผู้ใช้ใหม่ (เพิ่ม 2026-09-12) — อ้างอิงจาก [[../../01-requirements/01-spec/20260912-01-account-registration-approval|20260912-01-account-registration-approval]], BL-019, BL-020 (3) ดู/ค้นหาผลงานที่เผยแพร่แล้วแบบไม่ login (เพิ่ม 2026-09-12) — บทบาท **บุคคลทั่วไป** อ้างอิงจาก [[../../01-requirements/01-spec/20260912-02-public-view-search-published-works|20260912-02-public-view-search-published-works]], BL-021 ทุก flow อ้างอิง entity `StudentWork`/`UserAccount` ใน [[architecture|architecture.md]]

> ยังไม่ครอบคลุมบทบาท **ชุมชน** และ **นักท่องเที่ยวแบบมีบัญชี** (เขียนรีวิว/บันทึกสถานที่โปรด) — สิทธิ์การเข้าถึงของสองบทบาทนั้นยังเป็น Open Question ที่ยังไม่ปิด (ดู [[../../01-requirements/03-task/open-questions|open-questions]]) ไม่รวมอยู่ในไฟล์นี้ — **"บุคคลทั่วไป" ในตารางด้านล่างหมายถึงผู้เยี่ยมชมที่ไม่ login เลยเท่านั้น** แคบกว่าบทบาท "นักท่องเที่ยว" เต็มรูปแบบ

**สถานะการบังคับใช้:**
- **flow ตรวจสอบผลงานนิสิต (อัปเดต 2026-09-11):** บังคับใช้จริงแล้วทั้งสองระดับใน [[../01-prototypes/prototype-v2/README|prototype-v2]] — (1) UI ซ่อนปุ่ม/เมนูที่ไม่ตรงสิทธิ์ หลัง login ด้วย Firebase Authentication จริง และ (2) `LSH/firestore.rules` บังคับที่ backend ด้วย (ทดสอบยิง request ตรงข้าม UI แล้วว่าบล็อกจริง)
- **flow สมัคร/อนุมัติบัญชีผู้ใช้ใหม่ (อัปเดต 2026-09-12):** บังคับใช้จริงแล้วเช่นกัน — implement ใน [[../01-prototypes/prototype-v2/README|prototype-v2]] ทั้ง UI (หน้าสมัครสมาชิก + รายการรออนุมัติของอาจารย์ + แบนเนอร์แจ้งเตือนจำลอง) และ backend (`LSH/firestore.rules` บังคับ role/status ตอนสมัคร, จำกัด field ที่แก้ไขได้ตอนอนุมัติ) — ทดสอบยิง request ตรงข้าม UI แล้วว่าบล็อกจริง (ส่งผลงานทั้งที่บัญชียังไม่อนุมัติ, self-approve ตัวเอง, อ่านข้อมูล user คนอื่น)
- **flow ดูผลงานแบบ public (อัปเดต 2026-09-12):** บังคับใช้จริงแล้ว — หน้าใหม่ [[../01-prototypes/prototype-v2/README|prototype-v2/published-works.html]] อ่าน `LSHRequests` แบบไม่ login ได้ (ค้นหาตามชุมชนแบบ live) `LSH/firestore.rules` บังคับที่ backend ให้เห็นเฉพาะ `status='อนุมัติ'` เท่านั้น — ทดสอบยิง request ตรงข้าม UI แล้วว่าบล็อกจริงทั้งการอ่านเอกสารที่ยังไม่อนุมัติโดยตรง และการ list ทั้ง collection แบบไม่กรอง

## ตารางสิทธิ์

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|
| **นิสิต** (`role: student`) | - สมัครบัญชีผู้ใช้ใหม่ได้เอง ก่อนมีบัญชี (BL-019)<br>- ส่งผลงาน (คอนเทนต์) เข้าระบบเพื่อขออนุมัติ — **เฉพาะบัญชีที่สถานะ "approved" แล้วเท่านั้น** (FR-3.1)<br>- ส่งผลงานใหม่ได้อีกหลังผลงานไม่ผ่านการอนุมัติ<br>- เห็นเหตุผลที่อาจารย์ระบุเมื่อผลงานไม่ผ่านการอนุมัติ หรือบัญชีไม่ผ่านการอนุมัติ | - อนุมัติ/ไม่อนุมัติผลงาน (ของตนเองหรือของผู้อื่น) — เป็นสิทธิ์ของอาจารย์เท่านั้น<br>- เผยแพร่ผลงานให้บุคคลอื่นเห็นได้เองโดยไม่ผ่านการอนุมัติจากอาจารย์ก่อน (Business Rule กลับคำตัดสินใจ 2026-09-04)<br>- **login เข้าใช้งานฟีเจอร์หลักไม่ได้ ถ้าบัญชีอยู่ในสถานะ "รออนุมัติ" หรือ "ถูกปฏิเสธ"** (BL-019) — บัญชีที่ถูกปฏิเสธเป็นสถานะสิ้นสุด ต้องสมัครบัญชีใหม่เท่านั้น แก้ไข/ส่งซ้ำบัญชีเดิมไม่ได้ |
| **อาจารย์** (`role: teacher` ใน Firestore `users` จริง — คนละคำกับ `role: admin` ที่ entity `UserAccount` เชิงแนวคิดใช้ ดูตาราง Mapping ใน [[architecture|architecture.md]]) | - ดูรายการผลงานนิสิตที่รอพิจารณา (BL-018)<br>- อนุมัติผลงาน → เผยแพร่ได้<br>- ไม่อนุมัติผลงาน พร้อมระบุเหตุผลบังคับ<br>- ดูประวัติผลงานที่เคยตรวจสอบไปแล้ว (อนุมัติ/ไม่อนุมัติ)<br>- ได้รับอีเมลแจ้งเตือนเมื่อมีบัญชีผู้ใช้ใหม่รออนุมัติ (BL-020)<br>- ดูรายการบัญชีผู้ใช้ใหม่ที่รออนุมัติ และอนุมัติ/ไม่อนุมัติพร้อมระบุเหตุผลได้ (BL-020) | - ส่งผลงานแทนนิสิต (ไม่มีข้อกำหนดให้ทำได้ — บทบาทนี้ระบุไว้เฉพาะการตรวจสอบ/อนุมัติ) |
| **บุคคลทั่วไป** (ไม่ login — เพิ่ม 2026-09-12) | - ดูผลงานนิสิตที่มีสถานะ "อนุมัติ" (เผยแพร่แล้ว) เท่านั้น (BL-021)<br>- ค้นหา/กรองผลงานที่เผยแพร่แล้วตามชื่อชุมชนที่สนใจ (BL-021) | - ดู/เข้าถึงผลงานที่สถานะ "รอพิจารณา" หรือ "ไม่อนุมัติ" ไม่ว่าทางใด<br>- ทำการกระทำอื่นใดทั้งหมด (ส่งผลงาน, สมัครบัญชี, อนุมัติ/ไม่อนุมัติ, รีวิว, บันทึกสถานที่โปรด ฯลฯ) — ต้อง login เท่านั้น |

## สถานะบัญชี (Account Status) — เงื่อนไขเพิ่มเติมนอกเหนือจาก role

เฉพาะบัญชี **นิสิต** ที่สมัครเองเท่านั้นที่มีสถานะนี้ (บัญชีอาจารย์ provision โดย admin ถือเป็น approved ทันที ไม่ผ่าน flow นี้):

| สถานะ | เข้าใช้งานฟีเจอร์หลักได้ไหม |
|---|---|
| รออนุมัติ (pending_approval) | ไม่ได้ — รอให้อาจารย์อนุมัติก่อน |
| อนุมัติแล้ว (approved) | ได้ ตามสิทธิ์ role=นิสิตด้านบน |
| ไม่อนุมัติ (rejected) | ไม่ได้ — สถานะสิ้นสุด ต้องสมัครบัญชีใหม่เท่านั้น |

## ข้อสันนิษฐาน

- "ส่งผลงานใหม่ได้อีกหลังไม่ผ่านการอนุมัติ" ของนิสิต — สมมติว่า**ไม่จำกัดจำนวนครั้ง** ตามที่ระบุไว้ชั่วคราวใน spec เดิม จำนวนครั้งจริงยังเป็น Open Question ที่ยังไม่ปิด (ต้องยืนยันกับอาจารย์ที่ปรึกษา)

## คำถามที่ยังไม่มีคำตอบ (ไม่ได้เดาไว้ในตารางข้างต้น)

- นิสิตแก้ไข/ลบผลงานที่ส่งไปแล้วได้หรือไม่ก่อนอาจารย์ตรวจสอบ — ไม่มีระบุใน spec/backlog
- อาจารย์แก้ไขเนื้อหาผลงานของนิสิตได้หรือไม่ (เช่น แก้คำอธิบาย) หรือทำได้แค่อนุมัติ/ไม่อนุมัติ — ไม่มีระบุใน spec/backlog
