# ACL — สิทธิ์การเข้าถึง: ระบบตรวจสอบผลงานนิสิต

ตารางสิทธิ์นี้ครอบคลุมเฉพาะ 2 บทบาทที่เกี่ยวข้องกับ flow "ส่ง/ตรวจสอบผลงานนิสิต" ของ **Local Story Hub** (**อาจารย์** และ **นิสิต**) อ้างอิงจาก FR-3.1 ([[../../01-requirements/01-spec/local-story-hub|local-story-hub]]), BL-018 ([[../../01-requirements/03-task/product-backlog|product-backlog]]) และ entity `StudentWork`/`UserAccount` ใน [[architecture|architecture.md]]

> ยังไม่ครอบคลุมบทบาท **ชุมชน** และ **นักท่องเที่ยว** — สิทธิ์การเข้าถึงของสองบทบาทนั้นยังเป็น Open Question ที่ยังไม่ปิด (ดู [[../../01-requirements/03-task/open-questions|open-questions]]) ไม่รวมอยู่ในไฟล์นี้

## ตารางสิทธิ์

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|
| **นิสิต** (`role: student`) | - ส่งผลงาน (คอนเทนต์) เข้าระบบเพื่อขออนุมัติ (FR-3.1)<br>- ส่งผลงานใหม่ได้อีกหลังผลงานไม่ผ่านการอนุมัติ<br>- เห็นเหตุผลที่อาจารย์ระบุเมื่อผลงานไม่ผ่านการอนุมัติ | - อนุมัติ/ไม่อนุมัติผลงาน (ของตนเองหรือของผู้อื่น) — เป็นสิทธิ์ของอาจารย์เท่านั้น<br>- เผยแพร่ผลงานให้บุคคลอื่นเห็นได้เองโดยไม่ผ่านการอนุมัติจากอาจารย์ก่อน (Business Rule กลับคำตัดสินใจ 2026-09-04) |
| **อาจารย์** (`role: admin`) | - ดูรายการผลงานนิสิตที่รอพิจารณา (BL-018)<br>- อนุมัติผลงาน → เผยแพร่ได้<br>- ไม่อนุมัติผลงาน พร้อมระบุเหตุผลบังคับ<br>- ดูประวัติผลงานที่เคยตรวจสอบไปแล้ว (อนุมัติ/ไม่อนุมัติ) | - ส่งผลงานแทนนิสิต (ไม่มีข้อกำหนดให้ทำได้ — บทบาทนี้ระบุไว้เฉพาะการตรวจสอบ/อนุมัติ) |

## ข้อสันนิษฐาน

- "ส่งผลงานใหม่ได้อีกหลังไม่ผ่านการอนุมัติ" ของนิสิต — สมมติว่า**ไม่จำกัดจำนวนครั้ง** ตามที่ระบุไว้ชั่วคราวใน spec เดิม จำนวนครั้งจริงยังเป็น Open Question ที่ยังไม่ปิด (ต้องยืนยันกับอาจารย์ที่ปรึกษา)

## คำถามที่ยังไม่มีคำตอบ (ไม่ได้เดาไว้ในตารางข้างต้น)

- นิสิตแก้ไข/ลบผลงานที่ส่งไปแล้วได้หรือไม่ก่อนอาจารย์ตรวจสอบ — ไม่มีระบุใน spec/backlog
- อาจารย์แก้ไขเนื้อหาผลงานของนิสิตได้หรือไม่ (เช่น แก้คำอธิบาย) หรือทำได้แค่อนุมัติ/ไม่อนุมัติ — ไม่มีระบุใน spec/backlog
