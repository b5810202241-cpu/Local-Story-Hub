# DESIGN.md — Local Story Hub Design System

- **แนวทาง**: Earth tone / Minimalist / Muji-inspired
- **อ้างอิงจาก**: [[local-story-hub|local-story-hub]], [[20260822-01-it-log-pdpa-consent|20260822-01-it-log-pdpa-consent]] (ผ่าน [[../../01-requirements/01-spec/index|01-spec]])
- **สถานะ**: Draft — โทนสี/ตัวอักษร/spacing กำหนดได้แล้วเพราะเป็นรากฐานที่ไม่ผูกกับ Open Question ส่วนแพลตฟอร์ม (Website/Application) ที่ยังไม่ตัดสินใจ อาจกระทบ pattern บางจุด (ระบุไว้เป็นหมายเหตุในแต่ละ component)

Local Story Hub เล่าเรื่องธรรมชาติ ศิลปวัฒนธรรม และภูมิปัญญาของชุมชน — ดีไซน์จึงต้องถ่อมตัวพอที่จะให้ **เรื่องราวของชุมชนเป็นพระเอก** ไม่ใช่ตัวอินเทอร์เฟซ แนวทาง earth tone + minimalist สอดคล้องกับปรัชญาแบบ Muji: ไม่ตกแต่งเกินจำเป็น วัสดุ/สีสันดูจริงและอบอุ่น และใช้งานได้จริงกับผู้ใช้ทุกวัย โดยเฉพาะกลุ่มชุมชนที่มีผู้สูงอายุเป็นผู้ใช้หลัก ([[local-story-hub|local-story-hub]] FR-1.7)

## 1. Brand Identity & CI

### แนวคิดแบรนด์

Local Story Hub ไม่ใช่แพลตฟอร์มการตลาดที่ตะโกนขาย แต่เป็น "สมุดบันทึกร่วม" ของชุมชน — ดีไซน์ต้องรู้สึกเหมือนกระดาษ ไม้ และแสงธรรมชาติ มากกว่าหน้าจอเทคโนโลยีเย็นชา คุณค่าหลัก 3 ข้อที่ดีไซน์ต้องสื่อ:

| คุณค่า | หมายถึงในดีไซน์ |
|---|---|
| **ถ่อมตัว (Humble)** | ไม่มีองค์ประกอบตกแต่งที่ไม่มีหน้าที่ ไม่มี gradient ฉูดฉาด ไม่มี emoji/ไอคอนสีสดแทรกทุกที่ |
| **จริงใจ (Honest)** | สีและภาพต้องดูเป็นธรรมชาติ ไม่ผ่านฟิลเตอร์จัดจ้าน แม้ AI จะช่วยปรับภาพ (FR-1.1) ผลลัพธ์ก็ต้องยังดูสมจริง |
| **เข้าถึงง่าย (Accessible)** | ตัวอักษรใหญ่พอ คอนทราสต์สูงพอ ปุ่มกดง่าย โดยเฉพาะสำหรับผู้สูงอายุในชุมชน (FR-1.7 — Must) |

### Brand Voice & Tone

- เขียนแบบพูดคุย ไม่ใช้ศัพท์การตลาด ("มาเล่าเรื่องชุมชนของคุณกัน" ไม่ใช่ "ปลดล็อกศักยภาพคอนเทนต์ของคุณ")
- ข้อความระบบ (error, empty state) อธิบายตรง ๆ ว่าเกิดอะไรและควรทำอะไรต่อ ไม่ขอโทษพร่ำเพรื่อ ไม่ใช้ศัพท์เทคนิค
- Consent/Privacy copy (BL-015, BL-016) ต้องเขียนด้วยภาษาที่คนทั่วไปเข้าใจ ไม่ใช้ศัพท์กฎหมายล้วน ๆ

### Logo / Wordmark (แนวทาง ยังไม่มีไฟล์จริง)

- Wordmark ตัวอักษรล้วน ไม่มีสัญลักษณ์ประกอบซับซ้อน — ถ้าจะมีสัญลักษณ์ ให้เป็นเส้นเดียว (single-stroke) เรียบง่าย สื่อถึงเส้นทาง/หมุดหมาย (เชื่อมกับ FR-2.3 หมุดหมายเดินทาง) ไม่ใช่ตราสัญลักษณ์ที่ซับซ้อน
- ใช้สีเดียวเป็นหลัก (Ink หรือ Clay) บนพื้นหลังเรียบ — หลีกเลี่ยง gradient หรือเงา (shadow) บนโลโก้
- พื้นที่ว่างรอบโลโก้ (clear space) อย่างน้อยเท่าความสูงของตัวอักษร "L"

## 2. Design Tokens

### 2.1 Colors

พาเลตต Earth tone หลายเฉด ไม่ใช่แค่สีเดียว — แต่ละเฉดอ้างอิงวัสดุ/บริบทของชุมชนไทย เพื่อให้รู้สึกจำเพาะเจาะจง ไม่ใช่ "earth tone ทั่วไป"

| Token | Hex | ที่มา / การใช้งาน |
|---|---|---|
| `color-paper` | `#F3EEE4` | พื้นหลังหลัก — สีกระดาษสาไม่ฟอกขาว |
| `color-sand` | `#E7DFCF` | พื้นผิว section รอง, การ์ดเรียบ |
| `color-stone` | `#C9BFAC` | เส้นขอบ (border), divider — ใช้แทน shadow เป็นหลัก |
| `color-bark` | `#8A7F6C` | ข้อความรอง, ไอคอนที่ไม่ใช่ primary |
| `color-ink` | `#2E2A22` | ข้อความหลัก — น้ำตาลเข้มอมดำ ไม่ใช้ดำสนิท |
| `color-clay` | `#B0673F` | Accent หลัก / ปุ่มหลัก — สีดินเผา |
| `color-moss` | `#6B7355` | Accent รอง / สถานะสำเร็จ — สีใบไม้แห้ง |
| `color-ochre` | `#C99A44` | Highlight / เน้นความสนใจ — สีดินเหลือง |
| `color-indigo` | `#4C5B62` | ลิงก์ / ข้อมูลเสริม — อ้างอิงสีครามย้อมผ้าไทย |

**Semantic mapping** (ผูกกับสีหลักด้านบน ไม่ใช่สีใหม่ เพื่อคงความ minimalist):

| Semantic | ใช้สี | บริบท |
|---|---|---|
| `color-success` | `color-moss` | บันทึกสำเร็จ, เผยแพร่สำเร็จ |
| `color-warning` | `color-ochre` | ต้องตรวจสอบก่อนดำเนินการต่อ (เช่น รีวิว AI ก่อนโพสต์ FR-1.1) |
| `color-error` | `#A13D2C` (rust เข้ม แยกจาก `color-clay` เพื่อไม่ให้ปนกับปุ่มหลัก) | ข้อผิดพลาด, ปฏิเสธ |
| `color-info` | `color-indigo` | ลิงก์, ข้อความอธิบายเพิ่มเติม, PDPA notice |

**หลักการใช้สี**: จำกัด accent สีจัดจ้าน (`clay`, `ochre`) ไม่เกิน 1 จุดต่อหน้าจอสำหรับ call-to-action หลัก ส่วนใหญ่ของหน้าจอควรเป็น `paper` / `sand` / `ink` เพื่อให้ **ภาพถ่ายและเรื่องราวของชุมชนโดดเด่นที่สุด** ไม่ใช่ตัว UI

### 2.2 Typography

ใช้ **ฟอนต์เดียว (Sarabun)** ทั้งระบบ ต่างกันที่น้ำหนักและขนาดเท่านั้น — สอดคล้องกับปรัชญา Muji ที่ไม่ผสมฟอนต์หลายตระกูลโดยไม่จำเป็น และ Sarabun อ่านง่ายทั้งภาษาไทย/อังกฤษที่ขนาดใหญ่ เหมาะกับข้อกำหนดเรื่องผู้สูงอายุ (FR-1.7)

| Token | ขนาด | น้ำหนัก | Line-height | ใช้กับ |
|---|---|---|---|---|
| `text-display` | 40px / 2.5rem | 600 | 1.25 | หน้า Landing, ชื่อชุมชน |
| `text-h1` | 32px / 2rem | 600 | 1.3 | หัวข้อหลักของหน้า |
| `text-h2` | 26px / 1.625rem | 600 | 1.35 | หัวข้อ section |
| `text-h3` | 22px / 1.375rem | 600 | 1.4 | หัวข้อย่อย, ชื่อการ์ด |
| `text-body-lg` | **18px / 1.125rem** | 400 | 1.7 | **ขนาด body เริ่มต้นของทั้งระบบ** (ใหญ่กว่ามาตรฐานเว็บทั่วไปที่ 16px โดยตั้งใจ เพื่อรองรับผู้สูงอายุ) |
| `text-body` | 16px / 1rem | 400 | 1.6 | เนื้อหารอง, คำอธิบาย UI (ไม่ใช้กับเนื้อหาเรื่องราวหลัก) |
| `text-caption` | 14px / 0.875rem | 400 | 1.5 | metadata เท่านั้น (วันที่, ชื่อผู้เขียน) ห้ามใช้กับข้อความที่ต้องกดหรืออ่านเพื่อทำงานต่อ |

**Root font-size**: ตั้ง `16px` แต่ค่าเริ่มต้นของ body content เป็น `text-body-lg` (18px) ไม่ใช่ `text-body` — ต่างจากเว็บทั่วไปที่มักใช้ 16px เป็นค่าเริ่มต้น เพราะกลุ่มผู้ใช้หลักฝั่งชุมชนคือผู้สูงอายุ

### 2.3 Spacing & Layout

Grid แบบ 8px เดียวทั้งระบบ:

| Token | ค่า |
|---|---|
| `space-xs` | 4px |
| `space-sm` | 8px |
| `space-md` | 16px |
| `space-lg` | 24px |
| `space-xl` | 32px |
| `space-2xl` | 48px |
| `space-3xl` | 64px |
| `space-4xl` | 96px |

- เว้นระยะระหว่าง section อย่างน้อย `space-2xl` (48px) ขึ้นไป — แบบ Muji คือให้พื้นที่ว่าง "หายใจ" ไม่อัดแน่น
- Container กว้างสุด 1120px บนเดสก์ท็อป, margin ข้างอย่างน้อย `space-md` (16px) บนมือถือ

### 2.4 Radius, Elevation, Iconography

- **Radius**: `radius-sm` 4px (input, tag), `radius-md` 8px (ปุ่ม, การ์ด), `radius-lg` 16px (modal, bottom sheet) — โค้งน้อย ไม่ใช่ทรงแคปซูล/pill เต็มรูป
- **Elevation**: หลีกเลี่ยง drop-shadow เป็นหลัก ใช้เส้นขอบ 1px สี `color-stone` แทนการยกน้ำหนักด้วยเงา ยกเว้นองค์ประกอบลอย (เช่น Consent bottom sheet) ให้ใช้เงาบางที่สุดเท่าที่จำเป็น (`0 2px 12px rgba(46,42,34,0.08)`)
- **Iconography**: เส้น (outline) เดียว ความหนาเส้นสม่ำเสมอ ไม่มีไอคอน filled สีสด — ธีมไอคอนอ้างอิงธรรมชาติ/ชุมชน (ใบไม้, ภูเขา, เส้นทาง, บ้าน) มากกว่าไอคอนเทคโนโลยีทั่วไป
- **ภาพถ่าย**: โทนสีอบอุ่น แสงธรรมชาติ ไม่ใช้ฟิลเตอร์จัดจ้าน — ผลลัพธ์จาก AI ปรับภาพ (FR-1.1) ต้องคงโทนนี้ ไม่ใช่ปรับให้ฉูดฉาดขึ้น

## 3. UI Components & Pattern

### ปุ่ม (Button)

| ประเภท | พื้นหลัง | ข้อความ | ใช้เมื่อ |
|---|---|---|---|
| Primary | `color-clay` | `color-paper` | การกระทำหลักของหน้า (เผยแพร่, ยืนยัน) — มีได้ไม่เกิน 1 ปุ่มต่อหน้าจอ |
| Secondary | โปร่งใส + เส้นขอบ `color-stone` | `color-ink` | การกระทำรอง (ยกเลิก, ดูภายหลัง) |
| Text | ไม่มีพื้นหลัง/ขอบ | `color-indigo` | ลิงก์, การกระทำที่ไม่สำคัญมาก |

ปุ่มสูงอย่างน้อย 48px (touch target ใหญ่พอสำหรับผู้สูงอายุ) มุมโค้ง `radius-md`

### การ์ด (Story Card / Community Card)

พื้นหลัง `color-sand` หรือ `color-paper`, เส้นขอบ 1px `color-stone` (ไม่ใช้เงา), padding อย่างน้อย `space-md`, ภาพนำหน้าการ์ดสัดส่วน 4:3 หรือ 1:1 (ไม่บีบภาพจนเสียองค์ประกอบ) หัวข้อใช้ `text-h3`, เนื้อหาย่อใช้ `text-body`

### ฟอร์ม/Input

เส้นขอบเรียบ 1px `color-stone` มุมโค้ง `radius-sm`, label อยู่เหนือ input เสมอ (ไม่ใช้ placeholder แทน label เพื่อการเข้าถึงที่ดี), ขนาดตัวอักษร `text-body-lg`, ความสูง input อย่างน้อย 48px

### Consent Banner / Modal (PDPA — BL-015, BL-016)

- แสดงเป็น bottom sheet พื้นหลัง `color-paper` เส้นขอบบน `color-stone` เงาบางตามที่ระบุในหัวข้อ Elevation
- ข้อความอธิบายสั้น กระชับ ด้วย `text-body-lg` ไม่ใช้ `text-caption` (ต้องอ่านง่ายพอ ๆ กับเนื้อหาอื่น เพราะเป็นการขอความยินยอมจริง ไม่ใช่ fine print)
- ปุ่ม "ยินยอม" เป็น Primary, ปุ่ม "ปฏิเสธ"/"ตั้งค่า" เป็น Secondary วางเท่ากันไม่เอนเอียงให้กดยินยอมง่ายกว่า (dark pattern) — สอดคล้องกับหลัก PDPA
- `หมายเหตุ`: รูปแบบ granular vs ยอมรับ/ปฏิเสธทั้งหมด ยังเป็น Open Question ในสเปคต้นทาง (ดู [[../../01-requirements/03-task/open-questions|open-questions]]) — pattern นี้ออกแบบให้รองรับได้ทั้งสองแบบ (ถ้า granular ให้เพิ่มรายการ toggle ย่อยใต้ข้อความหลัก)

### ตัวสลับภาษา (Language Toggle — FR-2.2)

ปุ่ม text ธรรมดามุมขวาบนของหน้า แสดง "ไทย / EN" ไม่ใช้ธงชาติ (ธงอาจสื่อความหมายผิดสำหรับนักท่องเที่ยวนานาชาติ) ขนาดตัวอักษรไม่เล็กกว่า `text-body`

### โหมดอ่านง่าย (Accessibility baseline — FR-1.7, Must)

ไม่ใช่ "โหมดเสริม" ที่ต้องเปิดเอง แต่เป็น**ค่าเริ่มต้นของทั้งระบบ**: ตัวอักษร `text-body-lg` เป็นฐาน, คอนทราสต์ข้อความต่อพื้นหลังอย่างน้อย 4.5:1 ทุกจุด, ปุ่ม/ลิงก์ที่กดได้ต้องมีพื้นที่กดอย่างน้อย 48×48px, ไม่ใช้สีเพียงอย่างเดียวสื่อความหมายสำคัญ (เช่น error ต้องมีข้อความกำกับ ไม่ใช้แค่กรอบสีแดง)

### Empty / Loading state

ข้อความอธิบายตรง ๆ ด้วยน้ำเสียงแบบแบรนด์ (ดูหัวข้อ Brand Voice) เช่น "ยังไม่มีเรื่องราวจากชุมชนนี้" แทน "No data found" — ใช้ไอคอนเส้นเรียบประกอบ ไม่ใช้ spinner สีสันจัดจ้าน

## 4. หมายเหตุเรื่อง Open Question ที่กระทบดีไซน์

- **แพลตฟอร์ม (Website/Application)**: token และหลักการข้างต้นใช้ได้กับทั้งสองแพลตฟอร์ม แต่ pattern navigation ระดับบนสุด (เช่น bottom tab bar แบบแอป vs top nav แบบเว็บ) ยังสรุปไม่ได้จนกว่าจะตอบคำถามนี้ (ดู [[../../01-requirements/03-task/open-questions|open-questions]])
- **การแปลภาษา/TTS**: ถ้ามีเสียงพากย์ (text-to-speech) จะต้องเพิ่ม component ปุ่มเล่นเสียงในหน้าอ่านเรื่องราว ซึ่งยังไม่ได้ออกแบบไว้ในเอกสารนี้ รอคำตอบ Open Question ก่อน
