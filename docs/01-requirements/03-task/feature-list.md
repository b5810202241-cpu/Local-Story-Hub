## รายละเอียด

### 1. เครื่องมือ AI ช่วยสร้างคอนเทนต์สำหรับชุมชน — Must
ปรับภาพ, คิดแคปชัน, แปลภาษา (BL-001–003) เป็น Must เพราะตอบปัญหาหลัก "ชุมชนขาดคนทำ content" โดยตรง ส่วน SEO และ Content Suggestion (BL-004, BL-005) เป็น Should ในระดับ backlog item — ที่ระดับ Feature รวมเป็น Must เพราะเป็นชุดเครื่องมือเดียวกันที่ผู้ใช้คาดหวังว่าจะมาด้วยกัน

### 2. ระบบจัดการข้อมูลชุมชน — Must
พื้นที่กลางให้ชุมชนเก็บคอนเทนต์/ข้อมูลของตนเอง แทนการสร้างเพจใหม่ซ้ำทุกครั้งที่มีหน่วยงานมาจัดอบรม (BL-006) — ขอบเขตของ "ข้อมูล" ที่จัดการได้ยังเป็น Open Question ในสเปคต้นทาง

### 3. การออกแบบเพื่อการใช้งานง่าย (ผู้สูงอายุ) — Must
ระบุไว้ตรง ๆ ในสเปคว่าต้องมีตัวหนังสือขนาดใหญ่ ขั้นตอนไม่ซับซ้อน เพราะกลุ่มผู้ใช้หลักฝั่งชุมชนคือผู้สูงอายุ (BL-007) — เป็นเงื่อนไข Must ที่ตัดผ่านทุก feature ฝั่งชุมชน ไม่ใช่ฟีเจอร์แยกโดด ๆ

### 4. การสืบค้นและวางแผนท่องเที่ยว — Must
สืบค้นแหล่งท่องเที่ยวและอ่าน/ฟังเรื่องราวสองภาษา (BL-008, BL-009) เป็น Must เพราะแก้ปัญหาหลัก "ข้อมูลชุมชนกระจัดกระจาย" ของนักท่องเที่ยวโดยตรง ส่วนการวางแผนเส้นทาง/หมุดหมาย (BL-010) เป็น Should แต่จัดรวมไว้ในฟีเจอร์เดียวกันเพราะเป็น flow ต่อเนื่องกัน

### 5. การมีส่วนร่วมของนักท่องเที่ยว — Could
เขียนรีวิวและบันทึกสถานที่โปรด (BL-011, BL-012) เป็นฟีเจอร์เสริมความสะดวก ไม่ได้ผูกกับปัญหาหลักที่สเปคเน้นย้ำโดยตรง จึงเป็น Could ทั้ง feature

### 6. พื้นที่คอนเทนต์สำหรับนิสิตนิเทศศาสตร์ — Must
ตอบปัญหาที่ระบุตรง ๆ ว่านิสิตขาดช่องทางเผยแพร่ผลงานที่ช่วยชุมชนได้จริง (BL-013) — ยังมี Open Question เรื่องกระบวนการอนุมัติก่อนเผยแพร่

### 7. การปฏิบัติตามกฎหมาย IT และ PDPA — Must
เก็บ log 90 วัน, Consent Notice, และทางเลือกยินยอม/ปฏิเสธ (BL-014–016) เป็น Must เพราะเป็นข้อบังคับทางกฎหมาย ไม่ใช่ฟีเจอร์ทางเลือก ส่วนการบันทึกหลักฐาน consent (BL-017) เป็น Should เพราะเป็นกลไกสนับสนุนการพิสูจน์ ไม่ใช่ตัวข้อบังคับโดยตรง
