# การอนุมัติบัญชีผู้ใช้ใหม่โดยอาจารย์ที่ปรึกษา

- **วันที่บันทึก:** 2026-09-12
- **สถานะ:** Draft

## Context

ระบบ prototype ปัจจุบัน ([[../../02-design/01-prototypes/prototype-v2/README|prototype-v2]]) ใช้บัญชี Firebase Authentication ที่ admin สร้างไว้ล่วงหน้าด้วยมือเท่านั้น (u001-u004) ยังไม่มีช่องทางให้ผู้ใช้จริงสมัครบัญชีเอง ระหว่างคุยเรื่องนี้ (คำถาม "หน้าแรกควรสร้างบัญชีผู้ใช้ก่อนไหม") ผู้ใช้ตอบว่าต้องการเปิดให้สมัครบัญชีได้ แต่บัญชีใหม่ต้องรอการอนุมัติจากอาจารย์ที่ปรึกษาก่อนจึงจะ login เข้าใช้งานได้ — เป็นคำตอบต่อ Open Item ที่บันทึกไว้ใน [[../../02-design/02-technical/architecture|02-technical/architecture]] (§ Open Items ข้อ 9: ต้องตัดสินใจวิธี login จริงก่อนขึ้นระบบจริง) และเชื่อมโยงกับ Open Question เดิมเรื่อง "การยืนยันตัวตนป้องกันมิจฉาชีพแอบอ้าง" ในสเปคหลัก

## ต้นฉบับ (Verbatim จากผู้ใช้)

> ก็ให้อาจารย์ที่ปรึกษาเป็นผู้อนุมัติบัญชีใหม่ที่สมัครก่อนถึงจะล็อคอินได้

## ขอบเขต (Scope)

- **In scope:** ผู้ใช้สมัครบัญชีใหม่ได้เอง (self-registration) เฉพาะบทบาทนิสิต; บัญชีใหม่อยู่ในสถานะ "รออนุมัติ" ทันทีหลังสมัคร; login เข้าใช้งานฟีเจอร์หลักของระบบไม่ได้จนกว่าอาจารย์ที่ปรึกษาจะอนุมัติ; แจ้งเตือนอาจารย์เมื่อมีบัญชีใหม่รออนุมัติ; บัญชีที่ไม่ได้รับอนุมัติต้องสมัครใหม่เท่านั้น (ไม่มีการแก้ไข/ส่งซ้ำบัญชีเดิม)
- **Out of scope:** บัญชีอาจารย์ยัง provision โดย admin เหมือนเดิม ไม่เปิดให้สมัครเอง

## Functional Requirements

1. ผู้ใช้ใหม่ (นิสิต) กรอกข้อมูลเพื่อสมัครบัญชีเอง: **ชื่อ-นามสกุล, อีเมล, รหัสผ่าน**
2. บัญชีที่สมัครใหม่มีสถานะเริ่มต้นเป็น "รออนุมัติ" — เข้าใช้งานฟีเจอร์หลัก (ส่งผลงาน/ตรวจสอบผลงาน) ไม่ได้จนกว่าจะได้รับอนุมัติ
3. ระบบแจ้งเตือนอาจารย์ที่ปรึกษาทาง**อีเมลของอาจารย์**เมื่อมีบัญชีใหม่สมัครเข้ามารออนุมัติ
4. อาจารย์ที่ปรึกษาเห็นรายการบัญชีที่รออนุมัติ และกดอนุมัติ/ไม่อนุมัติพร้อมระบุเหตุผลได้ (รูปแบบคล้าย flow อนุมัติผลงานนิสิตที่มีอยู่แล้วใน FR-3.1)
5. บัญชีที่ได้รับอนุมัติแล้วจึง login เข้าใช้งานได้ตามสิทธิ์ของ role ตน (อ้างอิง [[../../02-design/02-technical/ACL|ACL.md]] เดิม)
6. บัญชีที่ไม่ได้รับอนุมัติ (ถูกปฏิเสธ) จะ login เข้าใช้งานไม่ได้อีก ระบบแจ้งเหตุผลที่ไม่อนุมัติกลับไปยังผู้สมัคร และผู้สมัครต้อง**สมัครบัญชีใหม่**เท่านั้นหากต้องการเข้าใช้งาน (ไม่มีการแก้ไข/ส่งคำขอซ้ำกับบัญชีเดิม)

## Business Rules

- **บัญชีใหม่ทุกบัญชีต้องผ่านการอนุมัติจากอาจารย์ที่ปรึกษาก่อนเสมอ** ไม่มีทางเข้าใช้งานฟีเจอร์หลักได้เองทันทีหลังสมัคร ไม่ว่ากรณีใด
- **เปิดให้สมัครบัญชีเองได้เฉพาะบทบาทนิสิตเท่านั้น** — บัญชีอาจารย์ที่ปรึกษายัง provision โดย admin เหมือนเดิม ไม่เปิดสมัครเอง (ยืนยันโดยผู้ใช้ 2026-09-12 — ดูหมายเหตุด้านล่าง)
- **บัญชีที่ไม่ได้รับอนุมัติเป็นสถานะสิ้นสุด (terminal)** — ไม่สามารถแก้ไขหรือขออนุมัติซ้ำกับบัญชีเดิมได้ ต้องสมัครบัญชีใหม่เท่านั้น

> **หมายเหตุ (2026-09-12):** คำตอบเรื่อง "สมัครได้เฉพาะบทบาทไหน" ที่ได้รับมาสั้นๆ ตอนแรก ("เปิดสมัครเฉพาะ role") ตีความว่าหมายถึงเฉพาะนิสิต — ผู้ใช้ยืนยันแล้วว่าตีความถูกต้อง
