# Open Questions Tracker

ทักษะนี้รวบรวม Open Questions จากทุกไฟล์ spec ของโปรเจกต์ Local Story Hub มาไว้ที่จุดเดียว
เพื่อให้พาไปคุยกับผู้มีส่วนได้ส่วนเสียได้ง่าย ไม่ตกหล่น — **ไม่มีหน้าที่ตอบหรือเดาคำตอบเอง**

repo นี้ทั้งหมดเป็น Obsidian vault เดียว (root คือโฟลเดอร์บนสุดของ repo ไม่ใช่ `docs/` — ดู `.obsidian/app.json` ที่ root: `newLinkFormat: relative`, `useMarkdownLinks: false`) — ทุก
ลิงก์ต้องเป็น wikilink แบบ relative path เท่านั้น

## เมื่อไรควรมอบงานต่อให้ agent `open-questions-tracker`

ถ้ามีไฟล์ spec จำนวนมาก หรือต้องการให้ทำงานแบบแยกบริบท ให้เรียกใช้ผ่าน Agent tool ด้วย
`subagent_type: open-questions-tracker` แทนการทำตามขั้นตอนด้านล่างเอง ทักษะนี้และ agent ใช้
วิธีการเดียวกัน

## ขั้นตอน

1. **List ไฟล์ spec ทั้งหมด** ใน `docs/01-requirements/01-spec/` (ไม่รวม `index.md`)

2. **อ่านแต่ละไฟล์** แล้วดึงเนื้อหาใต้หัวข้อ `## Open Questions` (หรือ `## Open Questions /
   สิ่งที่ยังไม่ชัดเจน`) มาเก็บเป็นรายการต่อไฟล์ — ไฟล์ที่ไม่มีหัวข้อนี้เลย ถือว่าไม่มี Open
   Question ค้าง ไม่ต้องรายงาน

3. **อ่าน** `docs/01-requirements/03-task/product-backlog.md` — หา backlog item ที่มีบรรทัด
   `**หมายเหตุ**` พูดถึง Open Question ของไฟล์ spec นั้น ๆ แล้วจับคู่ `BL-XXX` เข้ากับคำถามที่
   เกี่ยวข้องที่สุด (จับคู่ไม่ได้ชัดเจนให้ปล่อยว่าง ไม่ต้องเดา)

4. **จัดกลุ่มผู้ตอบที่แนะนำ** ต่อคำถาม (เป็นข้อเสนอแนะ ไม่ใช่คำตัดสิน):
   - ทิศทางวิชาการ/ขอบเขตโครงการ/เกณฑ์การประเมิน → **อาจารย์ที่ปรึกษา**
   - ความต้องการ/บริบท/ข้อมูลของชุมชนจริง → **ตัวแทนชุมชน**
   - เรื่องเทคนิค/กฎหมายที่ไม่ผูกฝ่ายใดฝ่ายเดียว (เช่น เลือกแพลตฟอร์ม, Data Controller) →
     **ควรถามทั้งสองฝ่ายร่วมกัน**

5. **regenerate ทั้งไฟล์** `docs/01-requirements/03-task/open-questions.md` ใหม่ทุกครั้ง
   (เป็น **snapshot สถานะปัจจุบัน** ไม่ใช่ log ประวัติ — ต่างจาก `05-log` ที่ต้อง append เท่านั้น)
   ตาม template:

   ```
   # Open Questions Tracker

   _อัปเดตล่าสุด: {YYYY-MM-DD} — ไฟล์นี้ regenerate ทุกครั้งที่รัน ไม่ใช่ log ประวัติ
   (ดูประวัติการเปลี่ยนแปลงที่ [[../../05-log/index|05-log]])_

   ## {ชื่อไฟล์ spec} ([[../01-spec/{filename}|{filename}]])

   - [ ] {คำถาม} — เกี่ยวข้องกับ: {BL-XXX, BL-YYY หรือ "ยังไม่มี backlog item ที่อ้างถึง"}
     แนะนำถาม: {อาจารย์ที่ปรึกษา / ตัวแทนชุมชน / ทั้งสองฝ่าย}
   ```

6. **วันที่ต้องรันคำสั่งหาวันที่จริงเสมอ** (เช่น `date +%Y-%m-%d`) ห้ามเดาจาก training data

7. เพิ่ม wikilink ไปยัง `open-questions.md` ใน `docs/01-requirements/03-task/index.md` ถ้า
   ยังไม่มี

## ข้อควรระวัง

- ห้ามตอบหรือเดาคำตอบของ Open Question เอง มีหน้าที่แค่รวบรวมและจัดหมวดผู้ควรตอบ
- ห้ามแก้ไขเนื้อหา Open Questions ในไฟล์ spec ต้นทาง หรือแก้ backlog — อ่านอย่างเดียว
- ถ้า Open Question ในสเปคถูกปิด/ลบไปแล้ว ไฟล์ tracker รอบใหม่จะไม่มีคำถามนั้นอีกโดยอัตโนมัติ
  เพราะ regenerate ทั้งไฟล์จากสถานะปัจจุบันเสมอ
- เอกสารในโปรเจกต์นี้เขียนเป็นภาษาไทย ให้ผลลัพธ์เป็นภาษาไทยเช่นกัน

## รายงานผลให้ผู้ใช้

- จำนวน Open Question ทั้งหมดที่พบ แยกตามไฟล์ spec
- จำนวนที่แนะนำให้ถามอาจารย์ที่ปรึกษา / ตัวแทนชุมชน / ทั้งสองฝ่าย
- ถ้ามีไฟล์ spec ที่ไม่มี Open Question เหลือแล้ว ให้ระบุว่า spec นั้นพร้อมเข้า `02-design`
  แล้ว (ตามกฎ gate ใน `CLAUDE.md`)
